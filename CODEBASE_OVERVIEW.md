## What this repo is for

This codebase is a training + tooling stack for a **vision-conditioned LLM** that answers questions / produces structured outputs about an **autonomous driving scene** using **6 surround-view camera images from nuScenes**.

At a high level:
- It uses a frozen CLIP ViT-B/16 backbone to turn each camera view into a grid of patch tokens.
- It projects those patch tokens into the LLM hidden size.
- It injects the vision tokens into the LLM via `inputs_embeds` (not via a multimodal HF model class).
- It fine-tunes the LLM primarily via **LoRA** (and optionally QLoRA), plus trains the vision projection / adapter layers.

There is also a separate dataset-creation pipeline that uses an external multimodal API (Gemini) to create annotations from 6-view artifacts.

## The “task at hand” (what the code is trying to achieve)

The training objective implemented here is:

- Input: (a) 6 camera views for a `sample_token` from nuScenes + (b) a text question.
- Target: a text answer (or structured JSON-as-text) that the LLM should generate.

Formally the model is trained with standard causal-LM loss where only the **answer tokens** are supervised; all prefix tokens (vision + prompt) are masked with label `-100`.

## Training dataset format (what `VisionNuDataset` consumes)

Training data is read from one or more JSON/JSONL files.
Each row is expected to contain:
- `sample_token` (nuScenes sample identifier)
- `question` (string)
- `answer` (string) — or another field specified by `config["target_field"]`

The trainer uses `sample_token` to locate the 6 camera images inside `config["nu_dataroot"]` via the nuScenes SDK.

## Architecture (how the model is assembled)

### Components

**A) Base LLM**
- Built with `transformers.AutoModelForCausalLM.from_pretrained(config["model_id"])`.
- Tokenizer is extended with **special delimiter tokens** for each camera view.
- Fine-tuning mode:
  - `tuning_mode == "lora"`: LoRA adapters only
  - `tuning_mode == "qlora"`: 4-bit quantization + LoRA adapters
  - otherwise: full fine-tuning

**B) DeepEncoderRuntime (vision encoder)**
- Implemented in `src/deepencoder/deepencoder_infer.py`.
- Encodes each view using a CLIP ViT-B/16-style vision transformer.
- CLIP backbone is frozen.
- A trainable projector maps CLIP patch dim (768) → LLM hidden dim (e.g. 896 for Qwen2.5-0.5B).
- Output per view is a grid of patch tokens: `[HW, d_model]` where `HW = 24×24 = 576`.

**C) VisionAdapter (view + position adaptation)**
- Implemented in `src/encoder-decoder/training/models/vision_adapter.py`.
- Adds:
  - A learned embedding per camera view
  - A learned positional embedding across the 576 patch positions
  - LayerNorm + dropout
- Returns **6 separate tensors** (one per view), not concatenated.

**D) SequenceBuilder (multimodal prefix assembly)**
- Implemented in `src/encoder-decoder/training/utils/sequence_builder.py`.
- Builds an embedding sequence in a fixed order:
  1. For each camera view:
     - `<cam_X_start>` embedding
     - view patch tokens (576)
     - `<cam_X_end>` embedding
  2. Text prompt embeddings
  3. Answer embeddings (training only)

This produces `inputs_embeds: [B, total_len, d_model]` that feeds directly into the base LLM.

### End-to-end forward path (training)

```
JSON row (sample_token, question, answer)
        |
        v
VisionNuDataset + DataLoader
  - loads images (optionally in worker processes)
  - tokenizes question (chat template) + answer
        |
        v
DeepEncoderRuntime
  - CLIP ViT-B/16 patch tokens per view
  - projector: 768 -> d_model
        |
        v
VisionAdapter
  - add view + positional embeddings
        |
        v
SequenceBuilder
  - [view delimiters + view tokens] + [prompt tokens] + [answer tokens]
        |
        v
LLM forward(inputs_embeds, labels)
  - labels supervise answer tokens only
        |
        v
loss
```

## Training loop behavior (what happens each step)

Implemented primarily in `src/encoder-decoder/training/core/trainer.py`:
- Builds `prompt_ids`, `answer_ids`, and `sample_tokens` in collate.
- Vision encoding has a “fast path”:
  - images are loaded in DataLoader workers and passed as tensors to the training step
  - GPU does the CLIP forward + projector forward in a batched call
- Builds `inputs_embeds` using the sequence builder.
- Computes loss and applies gradient accumulation.
- Uses AMP (`torch.autocast`) for fp16/bf16 runs; uses GradScaler when fp16.

Optimizer and scheduler:
- `AdamW` with param groups:
  - LLM trainable params (LoRA adapters or full fine-tune)
  - DeepEncoder projector params
  - VisionAdapter params
- Scheduler: cosine decay with warmup.

## Validation + inference sampling

Validation and periodic inference sampling are implemented in:
- `src/encoder-decoder/training/core/validation.py`

Key behavior:
- Validation loss uses the same “inputs_embeds + labels” pattern.
- Inference sampling periodically generates predictions and writes artifacts into the run directory.
- There is explicit support for sampling from train split and validation/test split.

## Checkpointing layout

Checkpoint utilities are in:
- `src/encoder-decoder/training/utils/checkpoints.py`

A run directory typically contains:
- `training_state_latest.pt` / `training_state_best.pt`
- `qwen2_lora_adapter_latest/` (PEFT adapter + resized embeddings)
- `vision_adapter_latest.pt`
- `projector_latest.pt`

Resume loads:
- optimizer + scheduler state
- LoRA adapters (LLM; and CLIP if enabled)
- projector + vision adapter weights
- AMP scaler state (fp16)

## Architectural “shape” summary

- Modality: 6-camera surround-view vision + text
- Vision encoder: frozen CLIP ViT-B/16 patch tokens
- Projection: trainable MLP/linear to LLM hidden size
- Fusion strategy: prefix-token injection via `inputs_embeds` + per-view delimiter tokens
- LLM adaptation: LoRA (default) or QLoRA
- Training objective: causal LM loss on answer tokens only
